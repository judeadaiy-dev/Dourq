# TeamHub

موقع إدارة فريق متكامل: Next.js (App Router) + Tailwind + Supabase، بواجهة عربية واتجاه RTL ولوحة ألوان أوف وايت وبني هادئة.

## الصفحات
- `/login` `/signup` تسجيل الدخول وإنشاء حساب — `/onboarding` إكمال الملف الشخصي — `/account` إعدادات الحساب (الصورة، التخصص، الخبرة، السيرة الذاتية، البريد وكلمة المرور)
- `/workspace` التواجد الحي — `/chat` قنوات محادثة عمودية، حضور حي لكل غرفة، مؤشرات قراءة فعلية، ورسائل صوتية ومرفقات وإشارات للأعضاء
- `/tasks` لوحة كانبان بإسناد وأولويات ومواعيد وتعليقات ومرفقات — `/people` دليل الفريق والبحث والتخصصات والتوفر
- مركز إشعارات لإسناد المهام والإشارات وتغييرات الحالة
- تبويب إدارة طلبات الانضمام يظهر فقط لمالك المساحة ذي البريد المعتمد `bariqaday@gmail.com`؛ الوصول محمي أيضًا بسياسات Supabase.
- تطبيق TeamHub قابل للتثبيت على الأجهزة المدعومة، مع أيقونة خاصة ووضع تشغيل مستقل وصفحة اتصال بديلة. تُحفظ الرسائل النصية التي تُرسل أثناء انقطاع الشبكة محليًا للمزامنة لاحقًا؛ لا تُخزّن المحادثات السابقة أو الحسابات أو المرفقات دون اتصال.
- الحسابات الجديدة تبقى خارج مساحة العمل إلى أن يوافق مالك المساحة على طلب الانضمام. بعد الموافقة، تصبح الغرف ومحادثاتها ومهام الفريق متاحة للأعضاء المعتمدين.
- الغرف متاحة للأعضاء المعتمدين؛ يمكنهم إنشاؤها، ويستطيع منشئ كل غرفة تعديل اسمها ووصفها أو حذفها. يمكن الرد على الرسائل والانتقال إلى الرسالة الأصلية. يمكن لمرسل الرسالة تعديل نصها خلال 10 دقائق فقط، وتُفرض المهلة بسياسة قاعدة البيانات؛ كما يمكنه حذفها. حذف الغرفة يزيل رسائلها ومرفقاتها. تظهر الرسائل المثبتة وإيصالات القراءة لجميع الأعضاء المعتمدين.

## التشغيل
1. أنشئ حساب المالك بالبريد المحدد في الدالة `th_ensure_profile` وأكّد البريد الإلكتروني لتفعيل صلاحيات المالك. الحسابات الجديدة تحتاج موافقة المالك قبل دخول مساحة العمل؛ ويظل تأكيد البريد الإلكتروني خاضعًا لإعدادات Supabase Auth.
2. خذ نسخة احتياطية من قاعدة البيانات، ثم شغّل `supabase/schema.sql` كاملاً في Supabase > SQL Editor. يتضمن ذلك موافقات العضوية وجداول الإشعارات وإيصالات قراءة الرسائل وسياساتها، ويحدّث سياسات الجداول ومخازن الصور والمرفقات الخاصة، ثم يعيد تحميل مخطط PostgREST.
3. سجّل الدخول إلى التطبيق بهذا الحساب. الحسابات التي أنشئت قبل تشغيل المخطط تحتاج تسجيل الدخول مجدداً لإنشاء ملفها الشخصي.
4. لا تُخزّن إعدادات البيئة أو المفاتيح في المستودع. محلياً، ضعها في ملف `.env.local` غير المتتبّع؛ وعلى Netlify، أضفها من إعدادات الموقع قبل البناء:
   - `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` إعدادان عامان يحتاجهما متصفح المستخدم للاتصال بـ Supabase؛ لا تضع فيهما أبداً مفتاح `service_role`.
   - `SUPABASE_SERVICE_ROLE_KEY` و`RESEND_API_KEY` سريان وخاصان بالخادم فقط.
   - `RESEND_FROM_EMAIL` عنوان مرسل موثّق لدى Resend، و`TEAMHUB_OWNER_EMAIL` بريد مالك المنصة، و`SITE_URL` رابط الموقع المنشور لإضافته إلى رسالة طلب الانضمام.
   - لا تُضف أيّاً من المفاتيح السرية إلى متغير يبدأ بـ `NEXT_PUBLIC_`، ولا ترفع ملفات `.env*` إلى Git.
   إذا لم تُضبط خدمة البريد، يبقى الحساب محجوباً وتظهر للمستخدم رسالة واضحة مع إمكانية إعادة المحاولة.
5. `npm install` ثم `npm run dev` وافتح http://localhost:3000
6. للنشر على Netlify، اربط مستودع GitHub وأضف متغيرات البيئة المطلوبة في إعدادات الموقع قبل بدء البناء. أعد النشر بعد تغييرها. يلزم HTTPS لتثبيت التطبيق بعد نشره؛ يظهر زر التثبيت في صفحة الترحيب والأجهزة التي لا تعرض التثبيت المباشر تتبع تعليمات المتصفح.

## الخصوصية
المحادثات ومرفقاتها وصور الحساب والسير الذاتية تتطلب عضوية معتمدة وروابط تنزيل مؤقتة. السيرة الذاتية PDF خاصة ولا تظهر إلا للأعضاء المعتمدين. رسائل الصوت تُسجّل على جهاز المستخدم وتُرسل مع مخطط الترددات المقاس، ولا يوجد اتصال صوتي مباشر. حذف الرسالة مسموح لمرسلها أو لمالك المساحة.

يلزم تشغيل مخطط Supabase قبل استخدام ميزات التخزين الجديدة. البناء المحلي لا يختبر سياسات قاعدة البيانات؛ اختبرها في مشروع Supabase قبل نشر بيانات حقيقية.
